# 插件库 MCP 健康度实施前置审计裁决

> 日期：2026-08-22（America/Los_Angeles）
>
> 审计对象：《插件库全仓 MCP 服务健康度根因审计与修复方案》修订版 v2
>
> 审计结论：**有条件通过；禁止按原文作为单一批次原样实施**

## 1. 裁决摘要

原方案的根因判断与 fail-closed 原则基本成立，但实施设计把五类不同所有权、不同授权条件的工作绑成一个“全量完成”目标：

1. CrabCode-Plugin 发布止血；
2. CrabCode generation=2 宿主和凭据系统重构；
3. Acosmi 后端源码、生产部署与回滚；
4. 跨云 WORM、门限签名和发布审批基础设施；
5. 第三方供应商合同、应用审批与真实租户验收。

后三类不能由插件仓代码提交证明完成，第三方审批更不能由实现者代签。把它们同时作为本仓交付条件会导致两种坏结果：要么安全止血被外部事项无限阻塞，要么用占位 JSON、未验签声明或未经授权的探测伪造闭环。因此本次按责任边界拆分，先完成插件仓可独立验证的安全基线；其余事项保持显式阻断，不宣称完成。

## 2. 通过项

以下原则通过审计并纳入本次实现：

- `published / enabled / activated / configured / authenticated / connected / callable` 必须分开；
- 未完成端到端认证、依赖、供应商资格和真实工具调用验证的连接器不得随插件自动执行；
- 退役、示例、供应商专属端点和 raw LSP 不能继续留在 `.mcp.json`；
- 不在启动窗口安装依赖，不发布浮动版本启动器；
- `requiredMcpServers` 必须与实际安全运行配置一致；
- `mediaops` 在可信 principal 产品合同闭合前不得作为 required sidecar；
- secret/token 不进仓库、文档、命令行或普通配置文件；
- 自动 CI 暂停，工作流只允许经 GitHub `workflow_dispatch` API 手动触发；所有合并前测试在本机执行；
- 现有安装更新必须通过新 generation 目录替换。已核对 CrabCode `updateResolvedPluginInstallation`：它发布唯一新缓存路径并原子切换 registry，不在旧目录上覆盖，因此新包删除 `.mcp.json` 不会在当前支持宿主中遗留旧文件。

## 3. 必须纠偏的设计

### 3.1 一次止血只提升一次版本

原方案要求 P0-0E 对 43 个包提升 patch，随后 P0-0B 再对 78 个包整体提升 patch。第二次全仓提升没有对应的 78 份用户可观察代码变化，会制造缓存、回滚、审计和客服噪声。

本次固定为：只对 43 个实际修改 MCP 发布字节的 marketplace 插件执行一次 `nextPatch`；manifest、marketplace、存在时的 package 与第一方 serverInfo 同步。未修改发布字节的其余包不升版。

### 3.2 不生成没有消费者的 generation=2 占位物

当前宿主不消费 `connector-profiles.json`、capability inventory 或 release lock。先在插件仓生成 63 个 profile、428 条 capability 分类和签名 lock 外形，既不能保护 generation=1，也容易让管理面误把“存在文件”解释成“能力已建成”。

本次不写伪 generation=2 产物。零远程执行通过删除发布配置和硬门禁实现；未来只有在宿主 schema、加载器、验签器和迁移测试同批可用时，才引入其最小必要 catalog。

### 3.3 OAuth callback 不能全局锁死 3118

把所有原生应用 loopback callback 固定为 `127.0.0.1:3118` 会制造端口占用单点，并把供应商差异隐藏成全局策略。原生应用 loopback redirect 应优先使用操作系统分配的可用端口、只监听 loopback，并用 PKCE/state 防截获；某供应商确实只接受固定回调时，必须在该 provider profile 中以真实注册/E2E 证据单独约束。

因此 `3118` 不作为本仓恢复远程连接的既定前提。CIMD、DCR、预注册 client 与供应商 redirect 匹配策略由 CrabCode 宿主独立安全设计评审决定。

### 3.4 不能把外部批准写成仓内完成项

跨云对象锁、HSM/离线 root、双人 IdP attestation、法务 WORM、供应商 eligibility lease 都是独立控制面建设，需要账号、预算、法务、数据治理和安全负责人真实批准。本次不创建假 key、假 verdict、假 WORM locator 或 `not-tested` 的生产 lock。

### 3.5 不对 428 个 prompt 文件做无消费者的机械改写

当前 generation=1 不识别 `connectorPolicy`，对 428 个文件批量加 frontmatter 不能形成运行时门禁，反而扩大 prompt 漂移面。本次依靠“插件自带远程 executable 为 0”阻断网络执行，并在 marketplace 明示受影响能力；真正的 callable 过滤与依赖索引必须与宿主消费者同批交付。

## 4. 本次实施范围

本仓立即实施以下安全基线：

1. 43 份 `.mcp.json` 收敛为 1 份，仅保留 `crabcode-html-video/html-video` 本地 stdio；
2. 远程 HTTP/SSE、外部服务 stdio、channel/wrapper、`mediaops` 与 12 个 raw LSP 发布配置归零；
3. `requiredMcpServers` 只允许 `crabcode-html-video: ["html-video"]`；
4. 43 个受影响 marketplace 插件各提升一次 patch，版本三方一致；
5. `html-video` serverInfo 从 package version 派生，消除硬编码漂移；
6. marketplace 对 42 个被暂停插件显示明确状态，不再把安装描述成可连接/可执行；
7. MCP validator 从 warning baseline 改为 emergency safe-baseline hard gate，未来任何第二份 `.mcp.json`、remote/SSE 或未允许 server 都直接失败；
8. 两个 GitHub Actions 工作流只保留 `workflow_dispatch`，无 push、pull_request 或 schedule；
9. 提供机器可读 containment inventory 与本机测试记录。

另对工作树既存的 `cn-legal-study` marketplace=`0.3.0` / manifest=`0.2.1` 漂移执行最小一致性修复：保留已经广告的 `0.3.0`，只将 manifest 对齐到 `0.3.0`，不为该无 MCP 字节变更的插件再制造 `0.3.1`。

## 5. 明确的关联方影响

- 已安装用户升级这 42 个插件后，其插件自带远程/外部 MCP 配置消失；旧 token 不删除，但本仓不再发起请求。
- `mediaops` 依赖 sidecar 的治理门禁会以 `MCP_INACTIVE` 停止，不能把手工草稿写成已治理产物。
- 12 个 LSP 插件不再借 MCP 路径启动；这表示错误声明被移除，不表示 LSP 产品化完成。
- standalone connector 插件在恢复前属于展示性占位，安装不会产生连接；marketplace 必须明确提示。
- crabwork 工作流仍可基于用户输入/文件运行；依赖连接器的步骤不可用，不能静默声称已取数。
- Acosmi、CrabCode、provider/legal/security/ops 的后续工作不与本提交合并，也不因本仓门禁通过而自动获得批准。

## 6. 合并门

只有同时满足以下条件，本仓交付后复核才通过：

```text
.mcp.json 文件数                    = 1
MCP server 数                       = 1
HTTP / SSE                          = 0 / 0
stdio                               = 1（html-video）
requiredMcpServers 非空插件数        = 1（html-video）
退役/示例/供应商专属/Claude URL 命中 = 0
raw LSP .mcp.json                   = 0
42 个暂停插件 marketplace 状态提示   = 42
43 个受影响插件版本提升次数           = 各 1 次
自动 workflow trigger               = 0
本机 typecheck/test/build/validate   = pass
html-video typecheck/test/dist smoke = pass
```

任何未满足项先修复，不合并、不推送。跨仓与外部事项继续作为 blocker，不得为了满足“全量”措辞伪造证据。
