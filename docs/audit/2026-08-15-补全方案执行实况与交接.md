## 2. ⚠ 已实证的方案偏差（三处，以代码为准）

方案原文写于审计轮，执行中实跑发现三处需要修正的判断。**接手会话请以本节为准。**

### 2.1 P1 的工作量被低估：`bash -n` 只是第一层

方案只做到语法检查。实跑后另有**四个同级缺陷**，方案完全没抓到（已全部修完，记此为教训）：

1. `validate-agent.sh` 的 `description: |` 是 YAML **块标量**，原提取器只读到标题行 `|`
   ⇒ 恒报「1 characters / 太短」。修了语法它照样不可用
2. `((n++))` 在 `n=0` 时返回退出码 1，`set -euo pipefail` 当场杀进程
   ⇒ 脚本在**第一条 warning** 处静默中止。`hook-linter.sh` 同款（它因被 `if !` 包住而
   侥幸幸存，但 `((total_errors++))` 不在被测上下文里，有错时不打印总结且多脚本只跑第一个）
3. **Windows 版 jq 输出 CRLF**，未剥离的 `\r` 让每次字符串比较与 `.hooks[$event]`
   取值静默落空 ⇒ 合法配置被判 4 处错。已统一经 `jqr()` 剥离
4. 示例 hook 把路径直接内插进 JSON 字面量，含引号的路径会产出非法 JSON（已改 `jq --arg`）

**教训**：`bash -n` 通过 ≠ 能用。改完脚本必须拿真实输入跑一遍。

### 2.2 P1.3 的**理由**对但需补一条：三个 agent 自己违反自家教义

方案说「`<example>` 检查与本插件 flat prose 规范相反」——**结论正确**
（`agent-development/SKILL.md` 的 `:28/:94/:340/:348` 明确教 prose 触发场景），
但方案没提：**plugin-dev 自己的三个 agent 描述全用 `<example>` transcript 形**，
与自家 SKILL.md 教义相反。

**本轮处置**：只删了校验器里那条与教义相反的检查（改为检查 prose 触发描述），
**没有改三个 agent 的 description 形态** —— 那会改变 agent 触发行为，属行为变更而非

### 2.5 位置参数差一：方案完全未预见的系统性缺陷（本轮清零）

主仓 `src/utils/argumentSubstitution.ts::substituteArguments` 把 `$N` 映射到
`parsedArgs[N]`，即 **`$0` 是第一个参数**。文档全线沿用 shell 惯例（`$1` = 第一个）。
不是读代码推断的，是直接调用该函数实跑：

```
'Deploy $1 to $2 using version $3' + "prod us-east 1.2.3"
  → "Deploy us-east to 1.2.3 using version "     ← 整体错位 + 末位静默为空
'Validate $1' + "src/app.js"  → "Validate "       ← 参数整个消失
```

不报错、只是拿错值，所以能在 171 处存活。已按围栏语言逐处分类后清零
（`851e23d` 三文件 36 处 + `963c78a` 其余），并升级为 doc-facts 规则
`command-arg-off-by-one`。

**分类是承重步骤**：同批 `$N` 里有 9 处是**正确用法**——真 shell 脚本参数
（`COMMAND_FILE="$1"`）与 perl 反向引用（`s/.../$1/`），机械全局替换会改坏它们。

### 行尾

`.gitattributes` 强制 `* text=auto eol=lf` 且 `*.sh text eol=lf`（注释里写明理由：
CRLF 会让 `#!/usr/bin/env bash` 变成 `bash\r`，Linux 上 exec 失败）。

**要检查的是索引（会被提交的 blob），不是工作副本。** 本仓大量 `.md` 在工作树里
本来就是 CRLF（检出态），而 `text=auto` 会在入索引时归一为 LF —— 拿工作副本判红
只会得到一串与提交内容无关的告警。唯一可靠的判据：

```bash
git ls-files --eol $(git diff --cached --name-only) | grep -vc "^i/lf"   # 期望 0
```

> ⚠ 本文初版给的配方 `git show :<file> | grep -c $'\r'` **不可用**（§2.4b）：
> `git show` 在 Windows 上会重新套用检出过滤器，量的不是 blob；而 `grep -c $'\r'`
> 在本机连正向对照都过不了（喂已知 CRLF 返 0）。这是「验证命令本身也要被验证」的
> 又一例 —— 该配方同时给出过假阳与假阴。

**位置参数零基**（§2.5）没有单条 grep 能表达——判据是「块内用了 `$1` 却从不用 `$0`」，
它就是 `lint:doc-facts` 的 `command-arg-off-by-one` 规则本身。跑闸门即复算。
