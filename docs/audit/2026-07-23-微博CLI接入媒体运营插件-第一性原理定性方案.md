## 1. 结论先行

微博官方 CLI 确实存在,且它的能力**恰好沿着本插件已有的那条断层线一分为二**——这不是巧合,而是整个方案的设计支点。

- **读侧能力**(热搜 / 趋势 / 搜索 / 用户画像)= 天然的*情报输入*,可无缝接进现有 research/trends 管线,风险低、价值高。
- **写侧能力**(发博 / 评论 / 点赞 / 关注 / 营销)= 实名身份下对真实平台的*不可逆动作*,这正是插件**刻意不做**的 "Gate B"(`publish-runbook.md:13`、`PRACTICE.md` 规则 9、`README.md:143-144`:"不提供真实平台 API 发布…不得伪造发布成功")。

**核心命题**不是"要不要接",而是:**如何让微博 CLI 成为现有门禁的真实末端,而绝不成为绕过门禁的第二条弱发布路径。** 用户已决定三层全接(Tier 0+1+2),因此本方案的重点从"要不要跨 Gate B"转为"跨过去之后如何让每一层都自洽于插件的不变量"。

---

## 2. 第一性原理拆解

把两边都还原到不可再分的内核:

**插件的存在理由(不可动摇的不变量)**:可审计 · 逐级门禁 · 真人审批 · 身份绑定 · 职责隔离 · **绝不伪造成功** · **绝不自动发布**。

**微博 CLI 的本质**:它是一个**外部能力/凭证载体**,把微博开放平台 70+ API 封装成子进程可调、可 `--output json` 的命令行。它带来两类本质不同的东西:

| 维度 | 读/分析类 | 写/动作类 |
| --- | --- | --- |
| 本质 | 把外部世界的信号*拉进来* | 以你的实名身份对世界*推出去* |
| 可逆性 | 完全可逆(只是数据) | 公开、准不可逆 |
| 对不变量 | 相容(当作**不可信外部数据**即可) | 直接触碰 Gate B |
| 花费 | credits/配额 | credits/配额 + 声誉 + 合规 |

**两条地基级结论**:

1. 微博 CLI 的**输出**必须被当作**不可信数据**(`PRACTICE.md` 规则 1)——热搜标题、搜索结果、他人评论本身可含提示注入,须走服务端快照 + 哈希 + 不可信标记,绝不直接当事实或指令。
2. 微博 CLI 的**登录态**必须被当作**一个密钥,而不是一个治理主体**——它绝不能被误认为插件的审批身份(MCP OAuth subject / host_principal)。这两个是**两个独立信任域**。

## 3. 官方 CLI 全量能力盘点(看官方文档的结果)

### 3.1 权威事实(npm registry 元数据 + 四源交叉印证)

- 包名 **`@weibo-ai/weibo-cli`**,当前 **v0.8.3**,MIT,**Node ≥18**,二进制名 **`weibo`**
- 安装:`npm i -g @weibo-ai/weibo-cli` 或 `curl -fsSL https://open.weibo.com/cli/install.sh | bash`
- 鉴权:**OAuth,且需先过微博实名认证**;内置 token 自动刷新、分页处理、错误重试
- 命令范式:**`weibo <group> <action> [flags]`**
- 全局标志:`--output json|table|yaml|raw`(部分文档含 `csv`)、`--token <token>`、`-h/--help`
- 计费:free **5 次/小时**;付费四档 credits——**¥29(3,000)/¥69(7,500)/¥299(32,000)/¥899(100,000)**
- 官方将 70+ API 归为 **6 模块**:内容发布 / 互动管理 / 内容检索 / 趋势分析 / 受众画像 / 营销自动化(抽奖·批量分发)
- action 带 **`/biz`(企业高权限·高 credits)、`/limited`(受限配额)、`/other`(查他人数据)** 分层后缀——直接映射成本与授权范围,方案须显式建模。

### 3.2 命名陷阱(必须区分,否则接错)

GitHub `jackwener/weibo-cli` 与 PyPI `weibo-cli` 是**社区工具,非官方**——它们靠**抓浏览器 cookie / 二维码**登录,与本插件安全模型正面冲突。**本方案只用 `@weibo-ai/weibo-cli`。**

### 3.3 全部命令组 × 插件处置(不落任何一个)

| 命令组 | 归属模块 | 读/写 | 插件处置 |
| --- | --- | --- | --- |
| `auth`(`login` / `--device` / `whoami` / `logout`) | 鉴权 | — | 由**部署者**在插件信任域外完成;插件只探测状态 |
| `statuses`(发博 / `friends_timeline` / `show_batch`) | 发布+检索 | 读+**写** | 读→Tier 0;发博→**Tier 1(Gate B 末端)** |
| `comments`(评论查看/发布) | 互动 | 读+**写** | 读→Tier 0;发→**Tier 2(互动治理轨)** |
| `attitudes`(点赞/表态) | 互动 | **写** | **Tier 2** |
| `friendships`(关注/取关) | 互动 | **写** | **Tier 2** |
| `search`(搜微博) | 检索 | 读 | **Tier 0** |
| `users` / `me`(用户/本人信息) | 检索+画像 | 读 | **Tier 0** |
| `tags`(话题/标签) | 发布 | 读+写 | 读→Tier 0;写话题随发博走 Tier 1 |
| `wbindex`(微博指数/趋势) | 趋势 | 读 | **Tier 0** |
| `short_url`(短链) | 工具 | — | 随发博的排版工具,Tier 1 内 |
| `commands`(`list` / `show`) | 元 | 读 | **落地时的叶子命令权威枚举来源** |
| `config` / `version` / `upgrade` / `cli doctor` | 元 | — | 供 `mediaops.doctor` 探测就绪度 |

### 3.4 诚实标注(联网可达性上限)

官方文档站是 JS SPA、npm 网页返回 403,机器无法拉到*叶子级 action* 全量。**上表命令组层是完整且权威的**;落地时叶子命令须以 **`weibo commands list` / `weibo commands show` 为准**并锁定版本,而非臆造命令名(臆造恰恰违背"看官方文档")。营销模块(抽奖/批量分发)具体命令多为 `/biz` 端点,同样以 `weibo commands list` 为准。

## 4. 定性方案:三层分级接入

### Tier 0 —— 读侧情报(先落地,价值/风险比最高)

把 `search / wbindex / statuses(timeline) / users / me / tags(读) / comments(读)` 封装成**能力受限的证据适配器**,喂给现有 `trends.ts` + `media-topic-research` + intake/research 管线。

- **落点**:`platforms/registry.ts` 新增 `weibo` 平台;research/trends 侧新增 weibo 适配器,`shell weibo … --output json`,像 `research.capture` 那样**对结果做服务端快照 + 字节/文本哈希**,整体标记**不可信外部数据**。
- **治理**:零写、零身份风险;唯一约束是配额与注入防护。

### Tier 1 —— 发博作为 Gate B 的真实末端

让 `weibo statuses update/biz` 成为**已完整过完 Media Gate + 审批链之后**的真实投递器——**追加**在 `publish.package` 之后,**不削弱**前面任何一环。

- **落点**:新增 `mediaops.publish.dispatch.weibo`,只消费**已 approved、已打包、哈希绑定**的候选;要求 `publisher` 角色 + **逐条真人显式确认**;调用后把 CLI 返回的**真实 mid/永久链接**作为 Gate B 权威证据回绑 packageId/contentHash;两阶段可恢复、幂等、失败 fail-closed。
- **红线**:无 CLI 真实成功载荷,**绝不**报"已发布"(呼应 `不得伪造发布成功`)。微博官方自身亦建议"对发文等写操作保留人工确认",与插件哲学同向。

### Tier 2 —— 互动/营销自动化(用户已选纳入;详见第 5 章平行治理轨)

`comments(发) / attitudes / friendships / 抽奖 / 批量分发`。这是与插件"不虚构读者反馈"、反操纵价值观**冲突最强**的一层,须建独立治理轨,不能复用文章门禁。

## 5. Tier 2 专章:它打破了前两层保住的一个对称性

- Tier 0 是**读**,安全。
- Tier 1 发的是**你自己那篇已过完 originality/editorial/legal/审批的文章**——被推出去的东西*本身已被治理*。
- Tier 2 的动作(评论 / 点赞 / 关注 / 抽奖 / 批量分发)是**写,但其"内容"不是那篇被门禁过的 ArticleDoc**:点赞没有文章;评论往往短而即时;批量分发把触达*乘以*;关注/取关是*关系*动作。

**结论**:现有 Media Gate 围绕 ArticleDoc 建,**天然覆盖不了 Tier 2**。Tier 2 需要一条**平行的、专为互动而建的治理轨**——否则退化成"刷量脚本",与插件全部价值观对撞;建了这条轨,它才与其余部分自洽。这是接入 Tier 2 后最关键、也最不显然的一条。

### 5.1 Tier 2 净新增的治理原语(缺一不可)

1. **互动策略对象(engagement policy)**:按 brand 配置——允许哪些动作、时/日配额上限、目标 allowlist/denylist、冷却时间、禁止关注 churn。部署者设定、版本化、像 `platform.rules` 一样查时效。
2. **配额/额度治理器(quota governor)**:同时建模 credits(¥ 真金)+ 微博自身限流 + 策略上限;超限即拒、**绝不重试风暴**(CLI 内置 retry 必须封顶)、显式暴露花费。Tier 1 亦复用,但 Tier 2 是压力源。
3. **反操纵硬护栏(不可覆盖)**:不伪造 / 不把 AI 代写的互动冒充自然人;不做协同性虚假行为(coordinated inauthentic behavior);不批量关注陌生人;评论若含事实主张,仍走 reference 防火墙 + statement 台账;负面/商业/敏感回复仍路由 `crablaw-cn`。
4. **写动作的独立确认模式**:逐条或逐批真人确认 + 真实预览;凡上规模(批量分发/抽奖)仍守 `requester≠approver`;成功只认 CLI 返回的真实 ID/permalink(同 Tier 1,不伪造成功)。
5. **微博 ToS/合规规则集**:hard-limit——AI 标识、实名、**抽奖须符合微博抽奖规则 + 中国有奖促销/广告法**、禁止平台 ToS 定义的自动化 spam。
6. **审计**:每个 Tier-2 动作连同真实平台响应,哈希链入同一 SQLite 审计日志。

### 5.2 Tier 2 落点

- `platforms/registry.ts` 的 `weibo` 加互动上限 + 硬规则;
- 新增技能 `media-engagement-gate`(与 `media-publish-gate` 平行);
- 新增工具 `mediaops.engagement.plan`(dry-run:将做什么、花多少、是否过策略)→ `mediaops.engagement.dispatch.weibo`(确认后执行、记真实 ID);抽奖/批量分发各为受限子流程;
- 复用 doctor/capabilities 发现 + credits 治理器;
- 评论作为内容,含主张时仍触 reference/editorial。

## 6. 关键张力与红线(第一性风险清单)

1. **身份域隔离**:微博 OAuth(实名)与插件 MCP-OAuth/host_principal 是**两个信任域**。微博登录态 = 密钥,**不得**冒充 requester/approver;`requester≠approver` 隔离不因接微博而松动。
2. **密钥管理**:token 存活于**部署者信任域**,不入库、不进日志、**不交给子代理**(既有铁律:子代理只回结构化数据,不碰 mediaops 状态/git)。
3. **不可逆 & 不伪造**:发博/互动=公开准不可逆;成功判定只认 CLI 真实返回的 mid/permalink。
4. **credits = 真金白银 + 限流**:5/hr 免费、四档付费;非交互编排易烧额度,CLI 内置重试须**封顶**,成本/配额在 doctor/capabilities 显式暴露。
5. **供应链纪律**:weibo-cli 是 pre-1.0、个人维护者(pythias)的第三方 npm。**不并入插件依赖图/dist,不进 SBOM**——按 Playwright/vnu 先例,做**部署者自备、`mediaops.doctor` 探测(`weibo version` / `auth whoami` / `cli doctor`)、缺失即 `DEPENDENCY_NOT_READY`** 的可选外部工具。保住 `dist/server.js` 自包含与 SBOM 同步。
6. **AI 标识合规**:发微博须携带**平台原生 AI 生成内容标识**(中国生成式 AI 标识规定),作为 `weibo` 平台一条 `hard-limit` 进 `platform.rules.get`。
7. **法律/实名**:实名身份下发布/互动,负面/商业/隐私内容继续路由 `crablaw-cn`,门禁不降级。

## 7. 落地次序(风险升序 0→1→2)

| 阶段 | 内容 | 为什么这个顺序 |
| --- | --- | --- |
| 1. Tier 0 | 读侧情报接入 research/trends | 零钱零风险下先把"子进程调用 + `--output json` + 配额治理器 + 不可信快照/防注入"这套管道跑硬 |
| 2. Tier 1 | 发博作为成熟文章门禁的 Gate B 末端 | 单个高价值写动作,借已成熟的 ArticleDoc 门禁 + 审批链 |
| 3. Tier 2 | 互动/营销自动化 | 依赖前两步验证过的 doctor 发现 + credits 治理器,再叠加净新增的"互动治理轨" |

此次序让配额治理器与依赖探测**先在便宜的读流量上硬化**,再让任何涉及金钱与声誉的写动作上线。

## 8. 明确不做(防过度工程)

不并依赖(不入 package.json/dist/SBOM)、不自动发博/自动互动(全程真人确认)、不重造微博客户端、不让微博成为绕过 Media Gate 的弱路径、不在插件内存微博密钥、不做无差别批量关注/骚扰、不伪造互动或读者反馈。

## 10. 实施前置条件(待用户在真机补齐)

1. **叶子命令权威导出**:装好 `@weibo-ai/weibo-cli` 后运行 `weibo commands list --output json`(必要时对关键组补 `weibo commands show <group>`),把叶子级命令 + 参数 + 所属 `/biz`/`/limited`/`/other` 分层全量导出——这是唯一能 100% "不拉下任何 cli 命令"并锁版本的来源。
2. **实名与鉴权就绪**:完成微博实名认证 + `weibo auth login`,确认 `weibo auth whoami` 可用。
3. **credits 档位确认**:确定采用哪一付费档(或 free),据此设配额治理器上限。
4. **合规确认**:确认发布/互动所需的 AI 标识形式与抽奖合规口径(是否需 `crablaw-cn` 预审)。

以上到位后,按第 7 章次序进入实施(届时另起实施方案 + 独立分支)。
