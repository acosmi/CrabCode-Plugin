## 4. 唯一阻断：`P1-REL-02`

历史 publisher workflow ID `336369746` 已通过 API 置为 `disabled_manually`，旧路径保留 fail-only tombstone，新 safe publisher 使用独立路径/身份；这些属于 defense-in-depth。

GitHub API 最终只读复核仍返回 3 条历史 run：

```text
32579374255  2e0b1266dcc4c34f8930cd589ce7aaedd6aa0f10
32579303978  c09298c49d2030392a5d388a8a4d997743c7870c
32050757636  1e808becab96e67e0684d8301411879eca674309
```

旧/新 workflow 仍可读取同一 repo-level `MIRROR_*` secrets；具 Actions write 权限者理论上可 enable→rerun→disable，瞬时 metadata 检查不能证明 queued attempt 已取消。删除负测会真实调用旧凭据，安全审批器拒绝在没有用户明确不可恢复删除授权时执行。

因此 safe publisher/auditor 已硬编码双门：tracked control evidence 必须为 `historical-runs-deleted`，且运行时 GitHub API 必须返回 old workflow `total_count=0`、`workflow_runs=[]`；当前会按设计失败。只有管理员明确授权并完成三条 run 的审计归档+删除（或另行完成旧 key 轮换/服务器 high-water 并同步实现对应机器门）后，才能关闭本项。
