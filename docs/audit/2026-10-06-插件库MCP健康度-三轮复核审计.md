### 1.3 方法

- **安装形态模拟**：`git archive HEAD plugins/<id>` 导出到空目录（无 `node_modules`、无开发产物），按宿主语义替换 `${CRABCODE_PLUGIN_ROOT}`、`${CRABCODE_PLUGIN_DATA}`、`${user_config.*}` 后，原样执行 `.mcp.json` 的 `command`/`args`/`env`。
- **MCP 探针**：最小 stdio JSON-RPC 客户端，执行 `initialize` → `notifications/initialized` → `tools/list` → `resources/list` → `prompts/list` → 指定 `tools/call`，并统计 stdout 中的非 JSON 行。长会话版本在同一进程内串行执行调用脚本。复现要点见 §8。
- **网络副作用测量**：每次探针使用独立的空 `BUN_INSTALL_CACHE_DIR`，调用结束后统计缓存中出现的包。
- **发行物复现**：分别用 Bun 1.4.2 与 1.3.11 安装依赖并重建，比较与已提交 `dist/` 的差异。
- **对照实验**：同一调用分别在原始 `.mcp.json`、前置 `--no-install`、插件根放置 `bunfig.toml`（`[install] auto = "disable"`）三种条件下执行。

### 2.3 F1（P1）Bun 运行时自动安装

**机制**：`.mcp.json` 以 `bun --cwd ${CRABCODE_PLUGIN_ROOT} …/dist/*.js` 启动，插件根没有 `node_modules`，Bun 的默认自动安装因此生效：运行时遇到无法解析的包导入时，直接从 registry 拉取**最新版本**。

**实测**（空缓存，安装形态）：

| 触发 | 拉取内容 | 锁定版本 |
| --- | --- | --- |
| 仅启动 + `tools/list`（两个服务） | 无 | — |
| `mediaops.doctor` | `@playwright/test`、`playwright`/`playwright-core` 1.63.0，`@axe-core/playwright`、`axe-core` 4.13.0，`vnu-jar` 26.10.2 | 1.61.1 / 4.12.1 / 26.7.15 |
| html-video `doctor`（未传 `install:true`） | 50 个包，含 `ffmpeg-static` 5.3.0、`canvas` 3.2.3、`prebuild-install` 7.1.3、`https-proxy-agent` 5.0.1 | `ffmpeg-static` 5.2.0 |

触发点：mediaops 的 `import("@playwright/test")` / `import("@axe-core/playwright")` 依赖探测；html-video 的 `createRequire(...)("ffmpeg-static")` 二进制探测与 linkedom 的 `require("canvas")`。

**影响**：

- 未锁定第三方代码在 sidecar 进程内执行，绕过 lockfile 与 SBOM（“200 个锁定组件”在运行时不成立）；与安全基线“install nothing on launch”的意图冲突（启动时不装，但首个工具调用时装）。
- mediaops `doctor` 在拉到 1.63.0 后报告 `fullMode: ready`，与固定的 Playwright 1.61.1/Chromium 组合不符，就绪结论失真。
- 离线或访问 registry 受限的网络中，相关工具调用可能长时间阻塞。

**对照修复验证**：前置 `--no-install`，或在插件根放置 `bunfig.toml`（`[install]` `auto = "disable"`），两种方式下：拉包数为 0；两个服务握手不变；mediaops `doctor` 如实返回 `DEPENDENCY_NOT_READY` 及各依赖 `installed:false`。

### 2.4 F2（P1）html-video：系统 ffmpeg 下渲染必败

**现象**：`renderFrames` 返回 `render_failed: [FFmpeg] FFmpeg binary not found at HYPERFRAMES_FFMPEG_PATH="ffmpeg"`；同时 `doctor` 报 ffmpeg `ok:true`。

**根因链**：

1. `packages/multi-segment/src/ffmpeg.ts` 的 `computeFfmpegPath` 在使用 PATH 上的 ffmpeg 时返回裸名 `"ffmpeg"`；
2. `src/tools/renderFrames.ts:84`（`previewFrame.ts:122` 同理）把该值写回 `HYPERFRAMES_FFMPEG_PATH`；
3. 上游 `@hyperframes/engine` `utils/ffmpegBinaries.js` 的 `getConfiguredBinary()` 对配置值执行 `path.resolve()`，裸名被解析为 `<插件根>/ffmpeg`，文件不存在即失败。

**验证**：同一调用设置 `CRABCODE_FFMPEG_PATH=/usr/bin/ffmpeg`（绝对路径）后成功，产物经 ffprobe 确认为 640×360 H.264、时长 1.000000s、4895 字节。

**为何漏检**：开发目录 `node_modules/ffmpeg-static/ffmpeg` 由 postinstall 下载了 78MB 二进制，解析结果是绝对路径；安装形态没有该文件，F1 自动装上的 `ffmpeg-static` 也不执行 postinstall（缓存中只有 `install.js`、无二进制），最终都回落到裸名。`tests/mcp-stdio.test.ts` 与 `tests/tools.test.ts` 只覆盖 `renderFrames` 的拒绝路径。

**修复方向**：PATH 命中时写回解析后的绝对路径；或写回前不覆盖该环境变量。

### 2.5 F3（P2）html-video：stdout 污染

一次 1 秒的成功渲染中，渲染器 logger（`console.log("[INFO] …")`）向 stdout 写出 38 行 `[INFO] [Render] …` / `[Render:trace] …`；失败路径同样会写。MCP stdio 传输要求 stdout 只承载 MCP 消息。宽松客户端会丢弃这些行，严格客户端会报协议错误；40 段 × 30 秒的长渲染会成比例放大。mediaops 在第二轮整段长会话中 stdout 非 JSON 行为 0。

**修复方向**：sidecar 启动时把 `console.log` / `console.info` 重定向到 stderr。

### 2.6 F4（P2）安装形态端到端测试缺口

`check:distribution` 的 dist-only 检查只验证冷启动与 `tools/list`。建议新增一条门禁：`git archive` 导出、空 `BUN_INSTALL_CACHE_DIR`、仅系统 ffmpeg，执行 `doctor` 与一次真实 `renderFrames`，并断言零拉包、渲染成功、stdout 无非 JSON 行。该门禁可同时覆盖 F1–F3。

### 2.7 F6（P2）校验器误判 `--no-install`

`src/policy/mcpContractValidator.ts` 用 `/\binstall\b/.test(joined)` 判定“启动时安装依赖”，`"bun --no-install …"` 命中该正则，会被报为 error。建议把它改为显式识别 `bun install` / `npm install` 等安装动作，并反向要求 bun 启动的 stdio 服务禁用自动安装（`--no-install` 或插件根 `bunfig.toml`）。

### 2.8 F7（P3）发行物复现依赖 Bun 版本

Bun 1.4.2 与 1.3.11 生成的运行时辅助代码不同；且 Bun 1.4.2 对 `file:` 依赖的安装布局会让 seek-shim 被打包两次。两个发行物在 Bun 1.3.11 下均逐字节可复现，不构成缺陷。但 media-ops `package.json` 未声明 `packageManager`，`check:distribution` 的 stale 报错也不提示版本，本地使用其他 Bun 版本时会被误导。

### 4.2 关闭原因（2026-08-22 根因审计 §2.5、§6.1、§7.5）

当时服务进程本身健康（可启动、38 个工具），关闭原因是**身份与错误语义未闭合**：

1. 默认配置没有 local-editorial 或可信 host principal，所有写工具都返回 `AUTHENTICATION_REQUIRED`，装上后无法使用却显示为已连接；
2. 业务错误装在普通 envelope 里，MCP `isError` 仍为 `false`，失败会伪装成成功；
3. 第一代宿主直接执行 `.mcp.json`，不理解 connector catalog 与 release lease，安全基线 v1 因此只放行 html-video。

恢复门槛为 §7.5 的 8 项：默认 fail-closed；只读工具匿名可用；写工具无主体时 `isError:true` + `AUTHENTICATION_REQUIRED`；local-editorial 需用户显式开启并有低保证提示；宿主注入主体，不让用户手写环境变量；团队审批在多真人 subject 可用前保持 blocked；禁止全角色静态账号伪造多人审批；“MCP 已连接”与“治理写工具可用”分开显示。0.4.4 满足上述条件后恢复。

### 4.3 当前开启方式与仍关闭的能力层

## 8. 复现要点

```bash
# 1) 安装形态副本
git archive HEAD plugins/crabcode-media-ops | tar -x -C <clean>/crabcode-media-ops --strip-components=2

# 2) 空缓存下执行 .mcp.json（替换宿主变量），调用 doctor 后统计拉包
BUN_INSTALL_CACHE_DIR=<empty> bun --no-env-file --cwd <clean>/crabcode-media-ops \
  <clean>/crabcode-media-ops/dist/server.js     # 经 stdio 发送 initialize / tools/list / tools/call
ls <empty> | grep '@[0-9]'                      # 非空即发生运行时拉包

# 3) 对照：在 args 前加 --no-install，或在插件根写入
printf '[install]\nauto = "disable"\n' > <clean>/crabcode-media-ops/bunfig.toml

# 4) F2：html-video 真实渲染（仅系统 ffmpeg 时失败；设置绝对路径后成功）
HYPERFRAMES_BROWSER_PATH=<headless_shell> CRABCODE_FFMPEG_PATH=/usr/bin/ffmpeg …  # renderFrames + confirmed:true

# 5) 发行物复现：使用 Bun 1.3.11 重新 bun install --frozen-lockfile 后构建，git status -- dist 应为空
```
